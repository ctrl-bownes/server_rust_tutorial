Rust Server Guide

Install, start and configure your own Rust dedicated server on Windows.

1 Setup

Everything is installed automatically by setup.bat. You only have to run it once.

Install the server

Download SteamCMD and the Rust dedicated server files.

  1. Run setup.bat

  2. Wait for the download to finish

    This can take a while. Do not close the window.

  3. Wait for «Setup finished!»

    When you see Setup finished!, press any key to close the window.
    Your server is now installed. 🎉

Check the installed files

Your batch files are stored inside rust_server. 

RustServer/
├── guide/
├── setup.bat
├── steamcmd/
└── rust_server/
	├── start_server.bat          # Start your Server.
	├── update_oxide.bat          # Install/update oxide.
	├── select_version.bat        # Switch between branches (main, staging, beta, ...).
	└── server_files/             # Your server files.
Good to know: setup.bat only installs the vanilla Rust server. Oxide can be installed later with update_oxide.bat. See Chapter 4 → Oxide for more information.

2 Start the server

Once the setup is finished, choose how you want to continue.

Choose how to continue

You can start immediately or configure the server first.

Option A

Start right away

Launch start_server.bat with the default settings.

Option B

Configure first

Install Oxide, choose a version or customize the map before launching.

Start the server

Launch the server and wait until it finishes loading.

  1. Open the rust_server folder

    Double-click start_server.bat.

  2. Wait for the server to load

    A console window opens and generates the map on the first launch. This can take a few minutes.

    Keep this window open: closing it stops the server.

Connect to your server

Connect locally using the Rust F1 console.

Launch Rust or Rust Staging depending on the version you installed. Press F1 to open the game console and enter:
client.connect localhost

Make yourself admin

Give your player server administrator permissions.

Go to Chapter 3 → Commands to configure your SteamID and admin commands.

3 Commands

Fill in your information once, then copy the generated commands.

Player information

Enter the Steam information used by the commands below.

Server administrator

Give yourself Rust server administrator permissions.

Run this command with your SteamID and username:
ownerid YOUR_STEAMID64 YOUR_STEAM_USERNAME
Save the change
Run this afterwards so the admin list is kept after a restart.
server.writecfg

Oxide commands

Check Oxide and configure its administrator group.

Check if Oxide is installed

If the command is unknown, Oxide is not installed yet.
oxide.version

Grant access to the admin group

Give the Oxide admin group access to every permission.
oxide.grant group admin *

Grant all permission to a User

Give the Oxide User access to every permission.
oxide.grant user YOUR_STEAM_USERNAME *

Add yourself to the admin group

Add the player from the information above to the Oxide admin group.
oxide.usergroup add YOUR_STEAM_USERNAME admin
Some commands require privileges. If you cannot execute them from the game console, use the server console.

Install a plugin

Add plugins to extend your Rust server with new features.

Important:
  • Oxide need to be installed
  • If /oxide/plugins is missing, make sure oxide is installed, and make sure to boot the server once with oxide installed, oxide will then generate it's own files.
  • Some plugins require additional configuration files or other plugins. Always check the plugin's instructions before installing it.
  • Some plugins require permissions. click here to see commands to give those permissions.

What is a plugin? Plugins are .cs files that add new features or commands to your Rust server. They require Oxide to be installed.
For example this plugin allow you to import skins directly from the workshop.

  1. Download a plugin

    Download the plugin you want as a .cs file.

  2. Open the plugins folder

    Go to: rust_server/server_files/oxide/plugins/

  3. Copy the plugin

    Place the .cs file directly inside the plugins folder.

  4. Start the server

    Oxide automatically detects the plugin and loads it.

  5. Check the plugin

    Use the server console to check for plugin errors. You can also check the oxide/logs/ folder.
Plugin folder: rust_server/server_files/oxide/plugins/
Tips: When importing a plugin, there is no need to restart or stop the server, it can be running. Oxide will automatically load the plugin.
Click here for some useful commands.

Choose the Rust version

Switch between the Main, Staging and Beta branches.

How to change the version 3 steps
1 Stop the server.
2 Run select_version.bat.
3 Select the branch and wait for SteamCMD.

Branches:
1
Main PUBLIC

The normal public Rust version. This is the standard choice for a regular server.

Works with Oxide.
2
Staging TESTING

The upcoming Rust version used for testing before changes reach the public branch.

May not work with Oxide.
3
Public Beta BETA

Enter the name of a public beta branch when prompted by the script.

May not work with Oxide.
4
Private Beta BETA

Enter the branch name and its password when prompted by the script.

May not work with Oxide.
5
Exit

Close the menu without changing anything.

Important: If you change the Rust version, run update_oxide.bat again afterwards. Changing branches can overwrite Oxide files.

Server settings

Change how the server starts and which map it loads.

For this, you will need to edit your start_server.bat file.
Facepunch Official Settings List.

STARTUP CONFIGURATION
EDIT
Your start_server.bat should look like this:
@echo off cd ./server_files/ RustDedicated.exe ^ -batchmode ^ +server.level "Procedural Map" ^ +server.seed 2147483647 ^ +server.worldsize 1000 ^ +server.maxplayers 10
^ = new line

MAP TYPE

Procedural Map

Let Rust generate a map automatically using a seed and world size.

Keep these settings:
+server.level "Procedural Map" +server.seed 2147483647 +server.worldsize 1000
Seed Controls which procedural map is generated.
World size Controls the size of the generated map.
MAP TYPE

Custom Map

Use an existing Rust custom map instead of generating a procedural map.

Get the map from a server

If you are playing on a server that uses a custom map, you can check which map the server is using from the Rust F1 console.

  1. Join the server

    Connect to the Rust server whose map you want to obtain.

  2. Open the F1 console

    Press F1 while you are connected to the server.

  3. Check the server information

    Use the F1 console to inspect the server information and identify the map being used.

Use the map on your server

Once you have a direct URL to the .map file, put it in your start_server.bat.
Use:
+server.levelurl "https://maps.rustmaps.com/288/e9ba372f1b224bde83ce68f7ce591864/procedural__4555_55mQZn0PsUm6EKRCl0x3GQ.map"
Do not keep both configurations. When using a custom map, remove the procedural map settings:

+server.level +server.seed +server.worldsize

Your startup configuration should use +server.levelurl instead.
If you're a content creator, Custom Maps are perfect for creating cinematics on the same map where you recorded your gameplay.

6 Network

Make your Rust server accessible to players outside your home network.

How it works

Understand the difference between your local IP and public IP before configuring your router.

Your computer normally has a local IP address. This address is only used inside your home network.

For example:
192.168.1.25
Your router also has a public IP address. This is the address other people on the Internet can reach.

When someone outside your home tries to connect to your Rust server, the connection first reaches your router. The router then needs to know which computer should receive that connection.

This is what port forwarding does.
Player Internet
→
Your Public IP Port 28015
→
Router Port forwarding
→
192.168.1.25 Your PC
→
RustDedicated Port 28015
Important: An address such as 192.168.1.25 is a local/private IP. Players on the Internet cannot normally connect directly to it.

Port forwarding

Forward the Rust server port from your router to your PC.

Before you start: Port forwarding is only needed if players outside your local network need to connect to your server.

If you are on the same local network, you can skip this section.
Rust's default game port is 28015 UDP. This is the port players use to connect to your server.

You can change the Rust port later, but for this guide we will use the default:
28015 UDP

  1. Find your local IP address

    Your router needs to know which computer is running the Rust server.

    Open Command Prompt and run:
    ipconfig
    Look for:
    • IPv4 Address — your computer's local IP.
    • Default Gateway — your router's local IP.
    For example: 
    IPv4 Address . . . . . . . . . : 192.168.1.25
Default Gateway . . . . . . . : 192.168.1.1
    Do not copy these addresses blindly. They are examples. Use the values shown by ipconfig on your own computer.

  2. Open your router

    Copy the Default Gateway from ipconfig and enter it into your web browser's address bar.

    Example:
    192.168.1.1
    This should open your router's administration page.

  3. Log in to your router

    Your router will ask for an administrator username and password.

    Modern routers often have this information printed on a sticker attached to the router.

    The router administrator password is not necessarily the same as your Wi-Fi password.
    Some older routers may use default credentials such as: 
    Username: admin
Password: admin

Username: admin
Password: password

Username: admin
Password: (blank)
    Important: These are only examples. There is no universal router username or password. Modern routers may use a unique administrator password or ask you to create one during the initial setup.

  4. Find Port Forwarding

    Every router has a different administration interface. Depending on the manufacturer, look for something similar to:
    • Port Forwarding
    • Port Forward
    • NAT Forwarding
    • Virtual Server
    • NAT Rules
    If you cannot find it, search your router model alongside "port forwarding".

  5. Create a port forwarding rule

    Create a new rule that sends incoming traffic on port 28015 to your computer's local IP.

    Using our example IP, the rule would look like: 
    Service name:   Rust Server
External port:  28015
Internal port:  28015
Internal IP:    192.168.1.25
Protocol:       UDP
    Remember: Replace 192.168.1.25 with the IPv4 address from your own ipconfig.
    What do these fields mean?

    External port is the port people on the Internet connect to.
    Internal port is the port your Rust server listens on.
    Internal IP is the local IP of the computer running RustDedicated.
    Protocol tells the router what type of network traffic to forward. Rust's game port uses UDP.

  6. Save the rule

    Click Save, Apply, or the equivalent button on your router.

    Your router may briefly restart its network service.

  7. Allow the server through Windows Firewall

    Your router is not the only thing that can block the connection. Windows Firewall can also prevent incoming traffic from reaching RustDedicated.
    Check Windows Firewall: Make sure RustDedicated is allowed to communicate through the firewall, or allow the Rust server's UDP port 28015.

  8. Find your public IP

    Players outside your home network need your public IP.

    You can find it by searching:
    what is my IP
    Privacy: Your public IP identifies your Internet connection. Do not post it publicly unless you have a reason to.

  9. Connect from outside your network

    Once the server is running and port forwarding is configured, a player outside your network can connect using:
    client.connect YOUR_PUBLIC_IP:28015
    Replace YOUR_PUBLIC_IP with your actual public IP address.

Local vs public connection

Use the correct address depending on where the player is.

Same PC

If Rust and your server are running on the same computer:
client.connect localhost:28015

Same local network

If another player is connected to the same router as your server:
client.connect YOUR_LOCAL_IP:28015
For example:
client.connect 192.168.1.25:28015

Outside your network

If the player is connecting over the Internet:
client.connect YOUR_PUBLIC_IP:28015

Keep your local IP stable

Prevent your port forwarding rule from breaking later.

Your router normally gives devices their local IP addresses automatically using DHCP.

That means your server PC might have 192.168.1.25 today but receive a different address later.

If that happens, your router may still forward port 28015 to the old IP.
Recommended: Create a DHCP reservation for the PC running your Rust server. This tells your router to keep giving that computer the same local IP address.
The exact location of this setting depends on your router. Look for names such as:
  • DHCP Reservation
  • Address Reservation
  • Static Lease
  • Reserved IP

Troubleshooting

Things to check if players cannot connect.

  • Make sure the Rust server is running.
  • Make sure +server.port matches the port you forwarded.
  • Make sure the forwarded protocol is UDP.
  • Make sure the internal IP is your server PC's current local IP.
  • Check Windows Firewall.
  • Make sure outside players are using your public IP, not your local IP.
  • Make sure you are testing from outside your home network when testing the public IP.
Still not working? Some Internet providers use CGNAT or other network configurations that prevent normal inbound port forwarding. If your router does not have a public IP assigned to it, normal port forwarding may not work.
Start simple: First make sure you can connect using localhost:28015. Then test from another device on your local network. Only after that should you test the public IP.
